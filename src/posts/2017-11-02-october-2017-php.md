<h2>Asynchronous stack traces: why await beats .then()</h2>
First up, Mathias Bynens has an interesting look into how JavaScript stack traces are generated, and <a href="https://mathiasbynens.be/notes/async-stack-traces">why await beats .then()</a> when it comes to debugging.

<h2>Writing speaking code & ineffective coding habits</h2>
As always I've been watching a bunch of recorded talks, but two of them really spoke to me. The first one is <a href="http://calebporzio.com/">Caleb Porzio's</a> talk at this year's <a href="http://2017.eriedayofcode.com/">Erie Day of Code</a>. His talk <a href="https://www.youtube.com/watch?time_continue=2&v=aeUyTkUCb6U">Writing Code That Speaks</a> reiterates how code is written way more times than it's written as he dives into the language expressed in the code.

The second talk is <a href="https://about.me/kevlin">Kevlin Henney</a>'s talk from the <a href="http://2016.istanbultechtalks.com/">2016 Istanbul Teck Talks</a> where he discusses <a href="https://www.youtube.com/watch?v=ZsHMHukIlJY">Seven Ineffective Coding Habits</a> that makes code harder to maintain.

<h2>HTTP/2 and APIs</h2>
I've previously written about some of the <a href="https://jesperjarlskov.dk/http2-what-and-why/">advantages of HTTP/2</a>, and I'm generally a proponent of the protocol upgrade. In his article <a href="https://blog.apisyouwonthate.com/lets-stop-building-apis-around-a-network-hack-9a68f7e83dd2">Let’s Stop Building APIs Around a Network Hack</a> Phil Sturgeon argues how HTTP/2 will help make APIs simpler and more performant, by deprecating concepts like <a href="http://jsonapi.org/format/#document-compound-documents">compound documents</a>.

<h2>Event-Driven Architecture</h2>
In his article about <a href="https://herbertograca.com/2017/10/05/event-driven-architecture/">Event-Driven Architecture</a> Herberto Graca gives some background to the concept and some of it's advantages and disadvantages. He also has some interesting examples of where using events can help clean an application's structure, as well as where it shouldn't be used.

<h2>Software architecture is failing</h2>
On a more negative note Alex Hudson has a piece claiming that <a href="https://www.alexhudson.com/2017/10/14/software-architecture-failing/">Software architecture is failing</a> in which he argues that some architectural patterns are being hyped so much that we as developers forget to be critical when choosing which makes sense for the problem we're trying to solve.
